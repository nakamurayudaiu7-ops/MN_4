# MN_4
MN実験II 4班

概要：「やった」を共有していいねする、シンプルなSNS風Webアプリ

フロントエンド：Next.js

バックエンド：Python FastAPI/Flask



必須：

・タイムライン

・投稿

・いいね機能



できたら：

・カテゴリ分け（筋トレ、宿題、家事...）とカテゴリ別ソート

・アカウント/削除キー

・グループ作成

・コメント機能

・タイマー機能との連携

・写真投稿

・「いいね」以外の評価




1. 基本設計（必須機能の設計図）
フロントエンドとバックエンドが連携するためには、「どんなデータをやり取りするか」を決める必要があります。ここを最初に決めることで、両チームが独立して作業を進められるようになります。
データベースの設計（例）
最初は複雑な関係性を持たせず、1つのテーブル（表）だけで完結させます。

id 整数 (またはUUID)
投稿の一意なID

content　文字列
「やった」内容（例：「課題終わらせた！」）

likes_count　整数
いいねの数（初期値は0）

created_at 日時
投稿された日時

APIの設計（フロントとバックの約束事）
フロントエンドからバックエンドに対して、以下の3つの窓口（エンドポイント）を用意します。
タイムライン取得 (GET /posts)
動き：フロントがこれにアクセスすると、バックエンドがデータベースから投稿一覧を新しい順に並べて返します。
新規投稿 (POST /posts)
動き：フロントが「名前」と「内容」のデータを送ると、バックエンドがデータベースに保存します。
いいね追加 (POST /posts/{id}/like)
動き：フロントが特定の投稿IDを指定してアクセスすると、バックエンドがその投稿の likes_count を1増やします。

2. 開発の手順（ロードマップ）
6人を3人ずつのチーム（フロント3名、バック3名）に分けた場合、以下のような手順で進めると効率的です。
ステップ1：環境構築と「開通テスト」（1〜2週目）
全員： GitHubのリポジトリを作成し、それぞれのPCで環境を構築します。
目標： バックエンドで「Hello」と返すだけの簡単なAPIを作り、フロントエンドの画面にその「Hello」を表示させます。これができれば、両者の連携は成功です。
ステップ2：並行開発（2〜4週目）
フロントエンド班： バックエンドの完成を待たずに、Next.jsで画面を作っていきます。最初はダミーのデータ（手書きの配列など）を使って、タイムラインや投稿フォームの見た目を作成します。
バックエンド班： FastAPIでデータベース（最初はSQLiteで十分です）を構築し、上で決めた3つのAPIを作成します。
ステップ3：結合とテスト（4〜5週目）
フロントエンドのダミーデータを外し、バックエンドのAPIから取得した本物のデータに置き換えます。
実際に投稿できるか、いいねが反映されるか、全員の環境でテストします。
ステップ4：拡張・デプロイ（時間が余ったら）
必須機能が動くようになったら、「できたら」の機能（カテゴリ分けなど）に着手します。
可能であれば、Vercel（フロント）やRender（バック）などの無料サービスを使って、インターネット上に公開してみましょう。
まずはこの「必須機能」の土台を固めることが、グループワーク成功の鍵になります。
